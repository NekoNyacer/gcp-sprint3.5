# 神秘種子與品種成長圖鑑

完成散步路線、成功打卡終點時抽取種子；取消、定位失敗、其他補給站
不會觸發抽取。每條路線最多一顆。任務種子獎勵本次不變更。

背包一律顯示神秘種子，種植時只需命名，不能選擇機率池。拾獲時
保存抽中的品種與設定版本；後臺後續停用機率池也不會改變已取得的種子。
原有通用／新手種子在種植時依當時的設定抽選。新種植樹木的品種名稱
在成長達到 30%「小樹」時揭曉；之前的四階段共用外觀。

初始示範值為每條路線 35% 掉落，池內權重合計 100：

| 品種 | 種子中的機率 | 每次完成路線的機率 |
| --- | ---: | ---: |
| 榕樹 | 30% | 10.5% |
| 樟樹 | 24% | 8.4% |
| 桂花 | 18% | 6.3% |
| 柿子 | 12% | 4.2% |
| 楓香 | 8% | 2.8% |
| 櫻花 | 5% | 1.75% |
| 銀杏 | 2% | 0.7% |
| 國泰小樹 | 1% | 0.35% |

這些是可逆的示範調整值，最終機率與額外每日上限仍待確認。每次出發
保存當時的掉落設定，發布新設定只影響之後出發的路線。

後臺 `/seedTypes` 可查看成長圖片、設定掉落開關／百分比、選擇使用的
機率池並編輯各品種相對權重。修改後沿用儲存草稿、檢閱、發布流程。
新建的任意品種名稱若尚無模型，會明示暫用榕樹模型。

`firebase/seed/cms-gameplay-2026-10-27.json` 是既有 2026-10-27 本機擴充檔
加入新玩法設定的可檢閱匯入檔，保留其中的商家、種植點與其他類別；
不是新取得的雲端匯出。匯入會替換記憶體草稿，仍須儲存並發布。
「合併擴充資料」保留現有營運編輯，不會覆寫相同 ID 的機率池權重。

八種植物以既有程序模型衍生不同葉色、葉形比例、樹幹色及花色。
遊戲的開花與金黃葉外觀是美術設定；結果階段維持小樹點圖示。
培育、收成、Demo／一般帳號資料隔離與同步方式沿用既有流程。
一般帳號仍屬既有客戶端回報的原型進度，並非新增可信步數驗證。

圖片由實際 Three.js 模型產生。安裝既有前臺依賴後，可在專案根目錄執行：

```powershell
node scripts/render-tree-atlas.mjs
npm --prefix cms run build -- --configuration development
node scripts/verify-seed-atlas.mjs
```

第一個指令產生前後臺共用的 60 張 PNG（八品種 × 四後期階段、八品種
× 三個 2D 模型部件、四共用早期階段）。後臺檢查指令使用本機測試資料
掛載實際編譯頁面，封鎖外部 HTTPS，檢查 1440、1024、390、320 px 的
橫向溢出及圖片載入，並產生後臺預覽與全品種成長總覽。

這次工作不包含部署或雲端資料寫入；既有公司 Firestore 寫入限制仍適用。
