# 兌換功能規格

狀態：已確認，可進入設計與實作

使用者可見功能名稱：兌換  
現行程式功能名稱：Shop  

> 本文件彙整 C 功能「兌換」的已確認需求。依產品負責人指示，本次不修改 `CONTEXT.md`。若本文件與既有總體規格中的舊版收成、商品目錄或 ESG 兌換規則衝突，實作此功能時以本文件的已確認決策為準，並將跨功能差異列入後續文件整併工作。

## Problem Statement

CAT WALK 需要讓使用者在完成大樹培育後，清楚理解成果具備什麼價值，並能自行決定將成果轉換為個人回饋或公益影響。

原先把 C 功能定位成小樹點商城，容易與既有「國泰優惠 App」的商品兌換功能重複，也會讓使用者不清楚應在哪一個 App 使用小樹點。舊版產品規格另曾設計為樹木每跨過 5,000 成長值便直接取得 50 點，之後再花點數兌換商品或 ESG 項目；這與本次確認的新方向不同。

本次確認的核心問題如下：

- 大樹完成培育後，使用者需要有明確且可信的成果領取與兌換流程。
- 回憶林中的樹木具有收藏與情感價值，不應因兌換而消失。
- 兌換功能不可與國泰優惠 App 的商品兌換職責重疊。
- 使用者需要在小樹點與公益投入之間做出清楚選擇。
- 具價值的兌換資格必須有期限、交易紀錄、失敗保護與防重複提交機制。
- Demo 需以 Firebase／GCP 後端呈現可信交易流程，但不串接正式國泰小樹點或真實公益金流。
- 頁面必須能在 Android 手機直向、明亮模式下穩定完成五分鐘展示流程。

## Solution

將原 C「商城」重新定位為「兌換」。每棵樹第一次達到 5,000 成長值時，地圖種樹頁顯示「領取成果」。使用者於七個曆日內主動領取後，系統建立一份有效 365 天的大樹兌換資格；樹木本身永久保留於回憶林。

使用者進入兌換頁後，可以查看國泰集團 mock 小樹點總額、可兌換大樹數量、最早到期資格、生涯里程碑及交易紀錄，並選擇以下用途：

- 使用 1、5、9 或 16 份大樹兌換資格，分別取得 10、50、100 或 200 點 mock 小樹點。
- 使用 5 份大樹兌換資格，投入當期固定公益計畫。使用者成果約當 NT$50，國泰配對加碼 NT$50，合計產生 NT$100 公益投入。

小樹點兌換成功後立即更新 mock 小樹點總額。公益投入只呈現投入成功或失敗，不追蹤後續匯款與公益執行。所有成功、後端已受理的失敗，以及已領取但逾 365 天未使用的資格到期事件，統一顯示於時間序紀錄。

後端沿用專案既有 Firebase 架構，由 TypeScript Firebase Functions 驗證方案、兌換資格、到期日與使用者身分，並以 Firestore transaction、FEFO 與 idempotency key 保證 Demo 交易一致性。

## User Stories

1. 身為使用者，我希望功能名稱清楚表達「兌換」，以便理解這裡不是商品商城。
2. 身為使用者，我希望在大樹第一次達到 5,000 成長值後看到可領取提示，以便知道培育已產生可用成果。
3. 身為使用者，我希望自行按下「領取成果」，以便感受到完成培育的儀式感。
4. 身為使用者，我希望領取成果時不受 GPS 距離限制，以便不必回到原種植地才能完成 Demo 流程。
5. 身為使用者，我希望可以同時擁有多棵待領大樹，以便培育其他樹時不被單一待領狀態阻擋。
6. 身為使用者，我希望清楚看到成果領取期限，以便在七個曆日內完成領取。
7. 身為使用者，我希望知道七天未領會使該次培育成果枯萎，以便理解未取得兌換資格的原因。
8. 身為使用者，我希望成果枯萎時樹木收藏仍被保留，以便過往回憶不會因錯過期限而消失。
9. 身為使用者，我希望每棵樹只在第一次達到 5,000 成長值時產生一份金錢性成果，以便規則容易理解。
10. 身為使用者，我希望樹木超過 5,000 成長值後仍能有外觀或收藏成長，以便持續培育不只為了金錢獎勵。
11. 身為使用者，我希望領取後取得一份明確的大樹兌換資格，以便稍後選擇點數或公益用途。
12. 身為使用者，我希望知道每份兌換資格的到期日，以便在 365 天內使用。
13. 身為使用者，我希望系統優先使用最早到期的資格，以便降低資格意外失效的風險。
14. 身為使用者，我希望大樹資格到期時只有兌換權失效，以便回憶林收藏及生涯數量不受影響。
15. 身為使用者，我希望在兌換首頁看到目前小樹點總額，以便理解現有回饋資產。
16. 身為使用者，我希望點擊小樹點旁的資訊圖示後得知明細應至國泰優惠 App 查看，以便知道正確查詢位置。
17. 身為使用者，我希望小樹點總額本身不會誤導我進入不存在的明細頁，以便避免無效導頁。
18. 身為使用者，我希望看到目前可兌換大樹數量，以便判斷可使用哪些方案。
19. 身為使用者，我希望看到最早到期的大樹數量與日期，以便安排兌換。
20. 身為使用者，我希望平時的到期資訊採一般資訊樣式，以免長期警告造成麻木。
21. 身為使用者，我希望接近到期時看到「即將到期」及剩餘天數，以便及時採取行動。
22. 身為使用者，我希望在同一頁比較 10、50、100、200 點方案，以便選擇符合需求的回饋。
23. 身為使用者，我希望每張方案卡直接顯示所需大樹數量，以便理解交換成本。
24. 身為使用者，我希望方案卡直接顯示「可兌換」或「還差 X 棵」，以便不必點擊後才知道狀態。
25. 身為使用者，我希望未達門檻的方案仍可點擊，以便查看差額說明。
26. 身為使用者，我希望未達門檻時只看到說明與關閉操作，以免誤以為可以強制兌換。
27. 身為使用者，我希望已達門檻時看到完整確認內容，以便在不可逆操作前再次核對。
28. 身為使用者，我希望確認框顯示兌換內容、使用資格、兌換後剩餘數量、目前點數與預計點數，以便做出知情決定。
29. 身為使用者，我希望確認框說明「回憶林收藏不受影響」，以免誤以為大樹會被刪除。
30. 身為使用者，我希望可以取消尚未送出的兌換，以便修正誤觸。
31. 身為使用者，我希望兌換送出後無法重複點擊，以免同一操作被執行多次。
32. 身為使用者，我希望小樹點兌換成功後立即入帳，以便立刻看到成果。
33. 身為使用者，我希望兌換成功後留在兌換首頁，以便查看更新後的點數與大樹餘額。
34. 身為使用者，我希望每次交易只處理一份方案，以便確認內容與交易紀錄保持簡單。
35. 身為使用者，我希望四個方案採相同視覺層級，以便自行判斷，而不是被系統預選或推薦。
36. 身為使用者，我希望在同一頁看到當期公益計畫，以便把培育成果投入生態保育。
37. 身為使用者，我希望清楚看到公益投入使用 5 棵大樹，以便理解門檻。
38. 身為使用者，我希望看到我的成果約當 NT$50、國泰加碼 NT$50，以便理解 NT$100 公益影響的來源。
39. 身為使用者，我希望公益確認框顯示計畫名稱、使用資格、金額拆分與剩餘數量，以便核對投入內容。
40. 身為使用者，我希望公益投入成功後可兌換大樹立即減少，以便看到正確餘額。
41. 身為使用者，我希望公益投入不改變小樹點總額，以便區分個人回饋與公益用途。
42. 身為使用者，我希望公益投入失敗時資格不被扣除，以便避免損失。
43. 身為使用者，我希望頁面清楚標示公益計畫為 Demo 模擬資料，以免誤認已與特定單位正式合作。
44. 身為使用者，我希望沒有可兌換大樹時仍能看到全部方案，以便知道下一個目標。
45. 身為使用者，我希望零庫存時能前往收藏培育大樹，以便繼續完成成果循環。
46. 身為使用者，我希望看到生涯累積完成的大樹數，以便兌換後仍保留長期成就感。
47. 身為使用者，我希望看到下一個生涯里程碑與進度，以便有長期使用目標。
48. 身為使用者，我希望兌換不會讓生涯里程碑倒退，以便永久保留培育成就。
49. 身為使用者，我希望首頁看到最近三筆紀錄，以便快速確認近期操作。
50. 身為使用者，我希望查看全部兌換、公益與到期紀錄，以便核對完整歷史。
51. 身為使用者，我希望成功與失敗交易依完成時間倒序排列，以便先看到最新狀況。
52. 身為使用者，我希望點擊紀錄後查看交易時間、數量、編號與結果，以便確認交易內容。
53. 身為使用者，我希望失敗明細只提供必要結果，不顯示難以理解的技術原因，以免增加疑慮。
54. 身為使用者，我希望失敗明細明確說明小樹點未入帳且資格未扣除，以便確認沒有損失。
55. 身為使用者，我希望已領取但逾 365 天未使用的資格留下到期紀錄，以便知道可兌換數量為何下降。
56. 身為使用者，我希望資格到期紀錄說明回憶林收藏不受影響，以便消除疑慮。
57. 身為使用者，我希望完全斷網且請求未送達時看到「未送出」，以便理解沒有建立交易。
58. 身為使用者，我希望後端已受理但處理失敗的操作出現在紀錄中，以便事後核對。
59. 身為使用者，我希望大樹資格資料載入失敗時能重新載入，以便恢復頁面。
60. 身為使用者，我希望小樹點總額載入失敗時看到 `--`，以免把過期或假的數字當成目前餘額。
61. 身為使用者，我希望小樹點服務不可用時仍能投入公益，以便部分服務故障不阻斷整個頁面。
62. 身為使用者，我希望未登入或 token 失效時回到既有登入流程，以便重新驗證身分。
63. 身為展示人員，我希望 Demo 使用者已有足夠與不足的方案狀態，以便展示兩種互動。
64. 身為展示人員，我希望 Demo 操作在同一次使用期間保留，以便呈現真實的餘額更新。
65. 身為展示人員，我希望能從測試工具重置兌換資料，以便重複展示相同流程。
66. 身為開發者，我希望兌換門檻集中設定，以便團隊後續調整數字時不必修改多處畫面與邏輯。
67. 身為開發者，我希望前端只傳方案識別碼，不傳可信價格與數量，以便防止竄改。

69. 身為開發者，我希望成功交易原子更新資格、mock 點數與交易紀錄，以便避免半完成狀態。
70. 身為開發者，我希望技術錯誤寫入 Cloud Logging，而不是暴露給使用者，以便排查問題並維持清楚體驗。

## Implementation Decisions

### 1. 功能邊界與命名

- 使用者可見名稱統一為「兌換」。
- App 底部頁籤由「樹屋」改為「兌換」。
- 頁面標題使用「兌換」。
- 為降低既有 Git 分支整併衝突，本階段暫時保留 Shop 模組、Store 與 `/shop` route 的程式命名。
- 完整交易紀錄使用 `/shop/history`。
- 不建立商品目錄，不在本 App 內使用小樹點兌換商品。
- 小樹點明細與實際使用引導至國泰優惠 App，但本功能不提供 deep link 或自動開啟外部 App。

### 2. 大樹成果狀態

- 每棵樹只在第一次達到 5,000 成長值時進入成果可領取狀態。
- 達到 10,000、15,000 或後續成長值不再產生金錢性成果。
- 大樹成果允許同時多筆待領，不保留舊版全帳號單一 `harvestReady` 限制。
- 領取操作位於地圖種樹頁，不位於兌換頁。
- 領取不要求約 150 公尺 proximity，也不受每日一次限制。
- 待領成果的七天期限使用 `Asia/Taipei` 曆日，於第七天 23:59:59 截止。
- 七天未領後，成果狀態改為已枯萎並永久失去兌換資格；樹木本身不死亡、不刪除。
- 成果領取成功後建立一份 entitlement，效期自領取日起 365 天，於第 365 天 23:59:59 截止。
- 所有期限均由可信 server timestamp 計算，不採信裝置時間。
- 領取逾期狀態由地圖種樹與收藏功能呈現；已領取 entitlement 的使用期限與到期事件由兌換功能呈現。

### 3. 兌換方案設定

Demo 初始方案如下：

| 方案識別 | 點數 | 所需大樹資格 |
|---|---:|---:|
| 小樹點 10 點 | 10 | 1 |
| 小樹點 50 點 | 50 | 5 |
| 小樹點 100 點 | 100 | 9 |
| 小樹點 200 點 | 200 | 16 |

- 一次交易只處理一份方案。
- 不提供交易份數選擇器。
- 四個方案不顯示推薦標籤。
- 方案價格與所需資格必須集中於版本化設定；畫面、提示、後端驗證與 Demo seed 使用相同合約。
- 前端 request 只包含 `optionId` 與 `idempotencyKey`，不可將前端提供的點數或資格數量視為可信資料。

### 4. 公益計畫設定

- Demo 當期計畫名稱為「台灣動植物保育計畫」。
- 固定使用 5 份大樹兌換資格。
- 使用者成果價值為 NT$50，國泰配對加碼 NT$50，總公益投入為 NT$100。
- 頁面使用「公益投入」而不是正式捐款或捐款收據用語。
- 公益交易只使用成功與失敗狀態，不追蹤匯款、執行或成果報告進度。
- 公益資料必須標示為 Demo 模擬資料，不宣稱與具名機構已建立正式合作。
- 前端 request 只包含 `campaignId` 與 `idempotencyKey`，公益金額與資格數量由後端可信設定決定。

### 5. 首頁資訊架構

- 目標裝置為 Android 手機直向。
- 只支援明亮模式。
- 四張小樹點方案卡以兩欄近正方形排列。
- 首頁順序為：標題與小樹點總額、資格摘要、四個點數方案、公益計畫、生涯里程碑、近期紀錄。
- 右上角顯示 mock 國泰集團小樹點總額與資訊圖示。
- 點擊資訊圖示後顯示五秒提示：「小樹點明細請至『國泰優惠 App』查看」。提示可提前關閉。
- 資格摘要顯示可兌換大樹總數、最早到期數量及日期。
- 距離到期超過 90 天時使用一般資訊樣式；90 天內顯示「即將到期」，30 天與 7 天內提高提醒層級。提醒不能只靠顏色表達。
- 方案卡直接顯示點數、所需大樹數與「可兌換／還差 X 棵」。
- 所有方案卡都可點擊，不以灰色 disabled 隱藏內容。
- 零資格時保留全部方案，並提供導向 `/collection` 的培育入口。

### 6. 確認、成功與失敗互動

- 未達門檻時顯示所需數、目前數與尚差數量，僅提供關閉操作。
- 已達門檻時顯示確認視窗，包含方案、使用資格、兌換後剩餘、目前點數、預計點數及不可撤銷提醒。
- 使用者文案使用「使用大樹兌換資格」，避免表示樹木遭刪除。
- 確認後按鈕進入處理狀態並禁止重複操作。
- 成功時立即更新 mock 小樹點、可用資格與近期紀錄。
- 成功提示關閉後留在兌換首頁，不自動跳轉且維持捲動位置。
- 公益成功不改變小樹點總額。
- 失敗時不扣資格、不入點，並使用非技術性說明。
- 完全未送達後端的網路失敗不建立交易；後端已受理的失敗建立失敗交易紀錄。

### 7. 生涯里程碑

- 里程碑使用生涯完成大樹數，不使用目前可兌換資格數。
- Demo 門檻為 10、50、100、200、500、1,000 棵。
- 里程碑只顯示成就與下一目標，不發放點數、徽章或外觀。
- 兌換、公益投入或資格到期不會降低生涯累積數。

### 8. 交易紀錄

- 首頁顯示最近三筆，完整紀錄顯示同一份倒序時間軸。
- 支援小樹點成功、小樹點失敗、公益成功、公益失敗及 entitlement 到期事件。
- 點擊紀錄以 modal 顯示明細，不新增第三層 route。
- 成功與失敗交易明細顯示類型、交易編號、時間、使用或預計使用數量、點數／公益金額及結果。
- 失敗原因不顯示技術細節；後端技術錯誤寫入 Cloud Logging。
- Entitlement 到期事件顯示到期數量、時間、已超過使用期限及收藏不受影響，不需要交易編號。
- 七天未領的枯萎成果不進入兌換紀錄。

### 9. Firebase／GCP 邊界

- 沿用 Ionic、Angular、NgRx Signal Store、Firebase Authentication、Cloud Firestore、TypeScript Firebase Functions、Firebase Hosting 與 Cloud Logging。
- 不新增 Cloud Run、Java 或 .NET 應用後端。
- 沿用單一 callable command `redeemReward`，操作類型調整為小樹點兌換與公益投入。
- Callable 驗證登入使用者、App Check、request schema、Demo data scope 與 idempotency key。
- 成功交易使用 Firestore transaction 原子完成資格驗證、FEFO 標記、mock wallet 更新、交易寫入與 command result 去重。
- 失敗紀錄需與成功 transaction rollback 邏輯分離，確保可預期的後端失敗能留下客觀紀錄且不扣資格。
- 真實國泰小樹點外部系統不在本 Demo 範圍；mock wallet 可以在 Firestore transaction 內立即更新。

### 10. Firestore 資料模型

需在現有使用者資料下新增或擴充以下概念：

- Tree：保存首次達到 5,000 的時間、成果領取期限、成果狀態及領取時間。
- Tree Entitlement：保存來源 tree、取得時間、到期時間、狀態、使用時間與關聯交易。
- Wallet：保存 mock 國泰小樹點總額。
- Transaction：保存交易類型、狀態、編號、請求資格數、點數或公益 snapshot、時間與 Demo 標記。
- Command Result：以 idempotency key 保存已處理結果，讓重送回傳同一結果。
- Redemption Option：保存版本化的小樹點方案。
- Charity Campaign：保存版本化的當期公益計畫與金額 snapshot。

Entitlement 狀態至少涵蓋：

- 可使用
- 已兌換小樹點
- 已投入公益
- 已過使用期限

Tree 成果狀態至少涵蓋：

- 尚未達標
- 七天內可領取
- 已領取
- 已枯萎

### 11. Demo 種子資料

Demo 使用者初始狀態：

- 小樹點總額 2,680 點。
- 可兌換大樹 7 棵。
- 生涯完成大樹 56 棵。
- 2 份資格於 2027-03-31 23:59 到期。
- 5 份資格於 2027-08-31 23:59 到期。
- 7 份資格都已完成領取，不包含待領或已枯萎成果。

Demo 必須能同時展示：

- 可立即兌換的 10 點與 50 點方案。
- 可立即執行的公益投入。
- 尚差 2 棵的 100 點方案。
- 尚差 11 棵的 200 點方案。
- 成功後即時更新餘額。
- 測試工具可重置上述資料；正式兌換頁不顯示重置功能。

### 12. 載入與錯誤狀態

- 大樹資格主資料載入失敗時，整頁顯示錯誤與重新載入。
- 小樹點總額載入失敗時顯示 `--`，且點數兌換不可成立。
- 小樹點總額失敗不阻斷公益投入。
- 交易紀錄載入失敗時保留主要兌換內容，紀錄區顯示局部重試。
- 不以靜默假資料掩蓋線上 API 失敗。
- Demo Mode 使用明確隔離的 seed repository，所有資料維持 Demo 標記，不與 normal data 合併。

## Testing Decisions

### 測試原則

- 測試外部可觀察行為，不測試私有方法或內部實作細節。
- 優先使用最高且最少的測試 seam。核心價值交易以 Firebase callable command 作為主要 seam；頁面互動以兌換 Store／Repository 公開介面及 Angular component 行為作為次要 seam。
- 真實小樹點外部 API 不在測試範圍，以 mock wallet contract 驗證立即入帳。
- 時間測試固定 `Asia/Taipei` server time，避免測試依賴執行機器時區。
- 每個測試都須驗證資格與 wallet 不會出現負數、重複扣除或半完成狀態。

### Firebase Functions／Firestore Emulator 測試

至少覆蓋：

1. 未登入者不能領取成果、兌換點數或投入公益。
2. 樹木首次達到 5,000 時進入七天可領取狀態。
3. 同一棵樹不能建立第二份成果。
4. 多棵樹可同時處於可領取狀態。
5. 第七天 23:59:59 前可以領取。
6. 截止後成果轉為已枯萎且不建立 entitlement。
7. 領取不要求 proximity。
8. 領取成功後到期日依 server time 加 365 天並落在當日 23:59:59。
9. 兌換使用 FEFO 選取最早到期 entitlement。
10. 1、5、9、16 份資格分別兌換正確 mock 點數。
11. 資格不足時不扣資格、不入點並建立適當失敗結果。
12. 公益成功使用 5 份資格且不增加 mock 點數。
13. 相同 idempotency key 重送只產生一次結果。
14. 兩個同時交易不能重複使用同一份 entitlement。
15. 成功交易同時更新 entitlement、wallet、transaction 與 command result。
16. 成功 transaction 任一步驟失敗時不可部分套用。
17. 後端已受理的可預期失敗留下失敗紀錄且不扣資格。
18. 365 天期限屆滿後資格不可使用並產生到期事件。
19. Demo 與 normal 資料不能交叉使用。
20. 前端竄改點數、所需資格或公益金額不影響後端可信計算。

### Angular／NgRx 測試

至少覆蓋：

1. 初始摘要正確顯示 2,680 點、7 棵與最早到期資料。
2. 四張卡在 7 棵時分別顯示正確的可兌換與差額狀態。
3. 未達門檻卡仍可點擊並顯示差額提示。
4. 已達門檻卡顯示正確確認內容。
5. 確認中禁止重複提交。
6. 取消不呼叫兌換 command。
7. 點數成功後更新總額、資格數與近期紀錄。
8. 公益成功後只更新資格數與紀錄。
9. 失敗後資格與點數保持不變。
10. 完全未送達的網路失敗不新增交易紀錄。
11. 資格資料失敗顯示整頁重試。
12. 點數總額失敗顯示 `--`，公益仍可操作。
13. 資訊圖示顯示國泰優惠 App 說明並在五秒後關閉。
14. 首頁只顯示最新三筆紀錄。
15. 完整紀錄依時間倒序排列。
16. 明細視窗顯示客觀資訊但不顯示技術錯誤。
17. 零資格狀態保留方案並可導向收藏。
18. 生涯里程碑不因兌換而倒退。
19. Android 手機直向寬度下四張卡維持兩欄且無文字溢位。
20. 鍵盤焦點、螢幕閱讀器標籤及狀態文字不只依賴顏色。

### 既有測試先例與新增 seam

- Client 目前已有 Angular TestBed 元件測試，可沿用相同測試框架。
- 專案文件已規劃 Firebase Emulator Suite 與 Security Rules 測試，但兌換 backend 尚未實作；此功能將新增 callable command 與 Firestore transaction 的 Emulator 測試 seam。
- Shop 頁目前為空殼，沒有可重用的兌換測試；應從公開 Store／Repository 行為開始建立測試，不對 placeholder 結構補無意義測試。

## Out of Scope

- 正式國泰小樹點 API 串接與正式點數入帳。
- 國泰優惠 App deep link、商品目錄與商品兌換。
- 真實捐款金流、捐款收據、合作契約或公益組織後續執行追蹤。
- 宣稱林業及自然保育署或其他單位已成為正式合作方。
- 讓使用者自行選擇多個公益計畫。
- 公益匯款中、已交付、成果報告等後續狀態。
- 一次交易兌換多份相同方案。
- 推薦、熱門或個人化兌換方案。
- Dark Mode、平板及桌面專用版型。
- 登入、註冊、小樹點帳戶綁定流程。
- 真實 GPS proximity 作為領取或兌換條件。
- 成果逾期後的復活、補領或客服申訴流程。
- 樹木死亡、病蟲害或完整枯萎動畫系統；「成果已枯萎」只代表未取得兌換資格。
- 更名 Shop 程式模組、資料夾與 route。
- 重新決定光能、水滴、肥料的產出值、加成值或每日上限。
- 生涯里程碑的額外點數、徽章或限定外觀獎勵。
- 更新專案根 `CONTEXT.md`。

## Further Notes

- 本規格明確取代舊版「每跨 5,000 成長值直接取得 50 mock 小樹點」與「取得點數後在本 App 兌換商品／ESG」的價值流程。
- 本規格亦取代舊版金錢性收成所使用的 150 公尺 proximity、每日一次收成與全帳號單一 `harvestReady` 限制。
- 光能、水滴與肥料的數值仍待跨組討論，不屬於兌換頁面的已確認決策。兌換只依賴「樹木第一次達到 5,000」事件。
- 小樹點總額在 Demo 中為 mock read model；畫面樣式應沿用現有小樹點品牌呈現，但不代表正式服務整合。
- 若未來串接正式國泰小樹點，Firestore transaction 無法與外部點數系統形成單一原子交易，屆時需要另行設計 outbox、重試、補償與對帳流程。本 Demo 不提前實作該正式整合複雜度。
- 現有 repository 尚未建立 Firebase Functions、Firestore Rules、兌換 Repository 或交易資料模型；文件中的 Firebase command 屬規劃基準，實作時需新增相應專案結構。
- 既有產品規格、系統設計與 Azure Boards backlog 仍包含舊版 harvest／catalog 敘事。依使用者指示，本次只新增此功能規格，不直接修改 `CONTEXT.md`；其他文件是否同步更新應由後續工作另行處理。
