# Task 模組規格

Status：`ready-for-agent`  
Confirmed：2026-09-11  
Language：Traditional Chinese

## Problem Statement

使用者需要透過簡單且有期限的定點健走任務取得培育大樹所需的水滴與肥料，同時清楚知道目的地、剩餘時間、定位是否符合及獎勵是否已入帳。現有 Task 頁只有占位內容，舊文件中的種植／取水／配送多階段任務也已不符合最新產品決策。

## Solution

提供每日、每週及活動三類單一目的地 Task。使用者選擇地區後瀏覽所有有效任務，從詳情頁使用獨立地圖／定位介面前往目的地；距離及定位精確度都不超過 10 公尺時解鎖確認。可信任命令以伺服器時間、定位證明、參加狀態及冪等鍵驗證後，原子完成任務並發放一次資源。

## User Stories

1. 作為使用者，我要選擇任務地區，讓列表只顯示我願意前往的區域。
2. 作為使用者，我要讓系統記住上次地區，讓我下次不用重新選擇。
3. 作為使用者，我要切換每日、每週及活動任務，讓不同期限的內容容易瀏覽。
4. 作為使用者，我要看到所選地區的所有有效任務，讓我能自由選擇目的地。
5. 作為使用者，我要先看到最快到期的未完成任務，避免錯過期限。
6. 作為使用者，我要在任務卡看到名稱、目的地、獎勵、倒數及狀態，快速判斷是否參與。
7. 作為使用者，我要在已有可用位置時看到距離，但瀏覽列表本身不應強迫我授權定位。
8. 作為使用者，我要進入任務詳情，查看完整說明、目的地、期限、獎勵及地圖整合區域。
9. 作為使用者，我要自動取得每日與每週任務，不需要逐一參加。
10. 作為使用者，我要明確參加活動任務，理解活動期限與獎勵後才進入進行中狀態。
11. 作為使用者，我要在開始導航時才被要求定位權限。
12. 作為使用者，我要透過 App 內建議路線前往目的地，但可以選擇其他實際走法。
13. 作為使用者，我要知道自己距離目的地還有多遠。
14. 作為使用者，我要在定位精確度不足時看到明確提示。
15. 作為使用者，我要在距離與精確度均不超過 10 公尺時手動確認完成，避免路過時自動領獎。
16. 作為使用者，我要在送出完成請求時看到載入狀態，且不能重複連點。
17. 作為使用者，我要在逾時後安全重試，不會因此重複取得資源。
18. 作為使用者，我要在完成後看到獎勵與最新庫存，確認資源已入帳。
19. 作為使用者，我要讓完成任務在當期列表標示完成，方便確認結果。
20. 作為使用者，我要在任務到期時立即停止完成操作，避免誤以為逾期仍有效。
21. 作為使用者，我要在最近 30 天歷史中查看已完成及已過期任務。
22. 作為使用者，我要開啟歷史任務的唯讀詳情，確認過去的目的地、獎勵及時間。
23. 作為離線使用者，我要查看最近快取的任務，但系統不能在無法可信任驗證時發獎。
24. 作為展示者，我要切換尚未抵達、精確度不足及可完成三種定位狀態，穩定展示所有主要分支。
25. 作為隱私敏感的使用者，我不要系統長期保存或記錄完成當下的原始座標。

## Implementation Decisions

- Task 是具有唯一 ID、明確開始與截止時間、單一公共目的地的不可變排程實例。
- 每日 Task 使用台灣日曆日；每週 Task 從星期一零時開始；活動 Task 使用明確期間。
- 每日及每週 Task 自動加入並只能發水滴；活動 Task 必須手動參加並只能發肥料；獎勵數量由版本化資料決定。
- 步數與光能不屬於 Task Domain；種樹改由 Collection Domain 負責。
- 每個 Task 實例最多完成及發獎一次。活動參加紀錄不可修改或取消。
- 從未參加的活動不進個人歷史；每日／每週未完成任務到期後進入歷史。
- 正常完成必須同時滿足目的地距離不超過 10 公尺、裝置回報精確度不超過 10 公尺、仍在期限內及目前在線。
- 定位層只提供座標、精確度、觀測時間與導航入口；地圖與導航內部不屬於本規格。
- 完成命令重新計算距離並以可信任時間驗證，不接受單純的 `arrived=true`。
- 完成命令使用冪等鍵，並在同一交易中寫入完成紀錄、不可變資源帳本及庫存。
- 原始使用者座標只用於請求驗證，不持久化、不寫入結構化 Log。
- 活動參加由 Client 建立受 Security Rules 保護的不可變 Firestore 紀錄，不新增第六個 Callable Function。
- Task 狀態由 Task Store 管理；資源庫存由共用 Progress Store 管理。
- 線上與 Seeded Demo Repository 暴露相同介面，支援可觀察更新與明確重新整理。
- Demo 使用三個固定定位狀態，不提供任意座標輸入。
- 第一版沿用 Ionic 元件及既有 Cathay 綠色 Theme，不要求任務主視覺圖片。

## Testing Decisions

- 測試外部可觀察行為，不斷言 Component 或 Store 的私有實作細節。
- 主要測試切面是 routed Task UI 加 Task Store，注入 Fake Repository 與 Fake Location Port。
- 覆蓋地區、Segment、排序、活動參加、定位阻擋、完成、冪等重試、到期及歷史流程。
- Firebase Emulator 測試可信任命令的期限、距離、精確度、參加狀態、重複完成、原子發獎與 Rules。
- Progress Store 整合測試確認完成結果只更新一份共用庫存。

## Out of Scope

- Google Maps 或 Navigation SDK 的內部實作。
- 種樹、樹木培育及小樹點收成。
- 步數同步與光能計算。
- 照片打卡。
- 正式 GPS 防偽、背景定位及商用反作弊。
- Android Local Notification 與 Firebase Cloud Messaging。
- 任務內容管理後台。
- 最終公共 POI 現勘、品牌及場域核可。

## Further Notes

- 暫定板橋與西湖 POI 只能存在版本化 Demo Seed，必須清楚標示尚未核可。
- 正常模式離線只能讀取快取，不得參加活動、完成或發獎。
- 即將到期門檻為每日剩兩小時、每週及活動剩 24 小時。
- 地圖／導航負責人與 Web／Android 能力邊界仍是外部未決事項。
