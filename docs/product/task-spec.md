# Task 模組規格

Status：`implemented-locally`（驗證結果以 CONTEXT.md 為準）

Confirmed：2026-10-28，使用者確認「採建議，開始實作」

Language：Traditional Chinese

本版取代 2026-09-11 的固定 10 公尺、僅座標驗證及依週期限制獎勵種類的規則。

## 完成與領獎

每日、每週、限時活動都是一筆有唯一 ID、起訖時間及單一公共目的地的排程實例。CMS 設定本期，不自動建立下一期。

| 設定 | 每日 | 每週 | 限時活動 |
| --- | --- | --- | --- |
| 預設所需路線步數 | 1,000 | 5,000 | 2,000 |
| 起算 | 台北當日 | 台北當週，週一零時起 | 明確參加活動之後 |
| 是否須參加 | 自動加入 | 自動加入 | 手動參加，不重設已記錄基準 |
| 預設抵達半徑 | 100 公尺 | 100 公尺 | 100 公尺 |

- CMS 可調整步數、抵達半徑，以及水滴／肥料／種子的單一獎勵種類與正整數數量；任務不發光能。半徑範圍為 1–10,000 公尺，種子單次最多 100 顆，以限制單筆資料大小。
- 不設健走分鐘數或限時走完步數的條件。任務自身的起訖時間仍有效。
- 首頁選擇種植點、取得有效路線、明確確認出發後，移動步數才計入任務。規劃中、閒置時移動、原地轉向都不計入任務；普通步數照常依既有規則產生光能，每台北日光能上限仍為 7,500。
- 可跨多條路線累積；終止路線保留已走步數。同一段散步可以推進多個任務，但每個任務都須滿足自己的抵達條件。
- 步數達標，且當下位置在指定半徑內，才記錄達標資格。定位沿用精確度不超過 10 公尺的限制；觀測不得超過 30 秒或來自超過 5 秒的未來時間。
- `進行中 → 待領取 → 已領取`：記錄達標時間不發獎；只有點擊待領彈窗的「完成任務」才入帳一次。關閉、返回、瀏覽詳情及靠近地點都不發獎。
- 待領資格在離開目的地後保留；領取時不須再次抵達，但須在任務截止前完成。沒有額外寬限期；已成功發獎的同一請求可安全重試取得回執。
- 發布新版本後重新檢查尚未領取的資格；已完成紀錄保留原任務／獎勵快照。下架任務保留已完成歷史。

## 網頁 Demo 與資料

- 本次全程網頁模擬，不接 Android 計步器、Health Connect、GPS 或背景步數。一般步數的開啟 App 讀取情境也以模擬資料表示。
- 使用共享 `LocationStore` 的模擬位置；Task 不再用獨立假抵達選項繞過首頁位置。此流程示意步數加座標門檻，不宣稱正式防作弊。
- `ProgressStore` 分別保存普通步數與路線合格步數，路線步數使用台北日期桶與跨日累積計數。活動報名快照跨日計數基準。
- Demo 的任務、資格與庫存只在本機記憶體；重整頁面重置。正常登入帳號使用其 UID 專屬 Firebase 紀錄，仍是客戶端回報的模擬步數。
- 任務獎勵更新同一份 `ProgressStore` 庫存。Demo 不保有另一份獎勵庫存；正常帳號領獎同步不重設首頁路線，也不停止培育計時器。
- 種子發獎時抽定隱藏品種，沿用已發布的啟用種子機率池；背包記錄任務目的地與取得時間，來源 ID 使用 `task:<taskId>`，不冒充散步路線取得。
- 正常帳號的 `completeTask` 命令接受 `join`、`qualify`、`claim` 操作，分別快照報名步數基準、保存達標資格、原子發獎。命令冪等鍵綁定任務及操作。
- 發獎在同一交易中更新完成紀錄、不可變資源帳本、庫存、命令回執；種子品種與進度 revision 一併保存。
- Security Rules 只允許擁有者讀取玩家資料，禁止客戶端直接寫入報名基準、達標資格、完成、帳本、權威庫存及進度。
- 原始玩家座標僅暫時驗證，不寫入 Firestore、Log 或完整軌跡。保存的抵達結果只有距離、精確度、達標步數與時間。

## 畫面與地圖

- 列表使用每日／每週／限時活動頁籤，搭配獎勵、地區與狀態篩選，白色緊湊卡片、橘色倒數與獎勵、待領狀態。
- 有待領資格的卡片直接開啟手動領獎彈窗。其他卡片進詳情；最近 30 天歷史保留已完成與已過期的個人任務。
- 詳情顯示任務說明、剩餘時間、共享位置、目的地、抵達半徑及路線步數。前往首頁散步的動作保留既有路線，不自動出發或代替目的地確認。
- 任務地圖與首頁路線／鏡頭狀態分開。第一次開詳情建立 Task 地圖，後續任務與詳情瀏覽重用同一 Mapbox 實例；離開時停止更新，銷毀服務時釋放。
- 地圖呈現位置與抵達範圍，不額外呼叫 Directions 或畫假道路。地圖失敗不妨礙查看文字與步數。

## 驗證

- 驗證普通／路線步數分離、確認出發與終止界線、台北日／週邊界、活動參加基準、並行任務及跨地區達標。
- 驗證距離、精確度、新鮮度、未參加／未開始／過期／下架阻擋，以及待領後離開仍可領取。
- 驗證關閉不發獎、手動領取、冪等重試、共用庫存保留、種子來源、身份切換及領獎期間移動／花費。
- 驗證 Task 地圖重用，以及實際編譯畫面在 320／390／430／1024 像素寬度的版面。本機畫面驗證使用隔離地圖替身並阻擋外部連線，不代表雲端或付費地圖驗收。
- 照片打卡、真實裝置計步、正式反作弊、真實獎勵與自動週期排程不在本次範圍。

## 本機展示

1. 使用網頁 Demo 身分；先在限時活動詳情按「參加活動」。每日／每週不需參加。
2. 到首頁選擇種植點、規劃路線並確認出發，再使用既有搖桿模擬移動。參加前累積的活動步數不追溯計入。
3. 達到所需路線步數，並靠近任務目的地至設定半徑內，即記錄待領資格；可以離開後到任務列表手動領獎。
4. 在待領彈窗按「返回」不發獎；按「完成任務」才增加共用庫存。種子可在背包查看取得地點。

短時間驗證時，可透過 CMS 將測試任務暫設為 10–20 步，並確認起訖時間有效，再儲存及發布；這不會改變程式的 1,000／5,000／2,000 步預設值。不要修改或發布雲端資料來代替本機驗證。正常登入帳號需先部署新版 `completeTask`、`saveWalkProgress`、`cmsCommand` 與 Firestore rules。
