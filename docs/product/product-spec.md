# Cathay Go｜大樹同行：產品規格

版本：1.0  
狀態：Grilling 結束，作為 Azure Boards 建單基準  
日期：2026-09-03

## 1. 產品摘要

`CAT-WALK` 是內部專案代碼，工作中的展示名稱為 `Cathay Go｜大樹同行`。產品以國泰大樹意象，而非貓咪，鼓勵上班族在下班後多走一段路：走路獲得養分、完成帶有目的的健走任務、在公共地點種下與培育大樹，最後看見持續成長的私人回憶林與 mock 小樹點回饋。

Demo 的主要價值不是證明正式金流或大規模營運，而是讓內部決策者在五分鐘內理解以下循環：

> 多走路 → 獲得光能／水滴／肥料 → 選擇一棵樹培育 → 樹與回憶持續成長 → 達成里程碑 → 示範小樹點兌換／ESG 捐贈

## 2. 目標、非目標與衡量方式

### 2.1 目標

- 讓上班族願意在下班通勤時多走一小段、且有明確目的。
- 以地點型持續大樹，創造可回訪的個人回憶與品牌連結。
- 向一般大眾說明小樹點概念，而不是只服務既有壽險 App 使用者。
- 於桌面瀏覽器完整示範；在政策與時間允許時提供 S22+ Android APK。

### 2.2 非目標

- 不串接真實小樹點、店家、付款、金流或正式會員資料。
- 不建立真實好友邀請、搜尋、轉移或共同帳務。
- 不支援任意地點的任務生成、正式反作弊、健康醫療用途或正式營運風控。
- 不製作 iOS、AR、3D 地圖、AI 照片辨識、CMS、Weather API 或 FCM 推播。
- 不製作 Java 或 .NET 應用後端。

### 2.3 Demo 成功條件

- 目前與前一版本的 Windows Chrome／Edge 可由登入走到 mock 小樹點兌換。
- 360×800 以上響應式版面可完成相同流程。
- 外部路由、Gemini、GPS、相機、GCP、登入或 WebGL 失敗時均有預先定義的退路。
- 五分鐘、兩分鐘種子狀態與預錄影片皆可用。

## 3. 使用者與主要情境

主要使用者是下班後通常直接通勤返家的上班族。使用者可設定每日步數目標，以及只保存在裝置上的住家／公司座標。App 依目前位置、下一個通勤目的地、可接受的額外步行時間與回程偏好，從當區已審核路線中挑選合適任務，不把使用者帶離熟悉通勤廊道太遠。

兩種活動模式：

1. 主動任務：使用者主動選擇種植、取水或養分配送任務，查看地圖與安全提醒，進行步行與拍照打卡。
2. 被動累積：目標產品可讀 Android 日步數；Demo 的 Must 以網頁模擬器重現，Health Connect 是 Could。

所有有效步數只計一次。主動任務中的步數包含於當日累計，不額外重複計步；任務完成另發其特定資源。

## 4. 導航與畫面

底部四個頁籤為「首頁」、「任務」、「森林」、「小樹點」。排行榜由首頁入口開啟；頭像選單包含個人設定、提醒、隱私與 Demo Mode。

必備畫面：

1. Google 登入／準備好的 Demo 身份。
2. 漸進式 onboarding：每日目標、可略過的本機住家／公司錨點、初始種子。
3. 首頁：今日步數、光能／水滴／肥料、最多三棵追蹤樹、下班提醒。
4. 每日／每週／活動任務清單、地區選擇與歷史入口。
5. 任務詳情、目的地、期限、獎勵及地圖／定位整合區域。
6. 活動參加、10 公尺抵達確認與完成獎勵結果。
8. 森林清單與私人回憶林地圖。
9. 樹木詳情、養分配置預覽、成長與收成。
10. mock 小樹點錢包、兌換目錄與 ESG 捐贈。
11. Demo 控制、五分鐘／兩分鐘種子與重設。

## 5. Onboarding

- 首次 Google 登入後選擇每日步數目標。
- 住家／公司位置為選填，精確座標只保存在本機；換裝置需重新設定。
- 後端只在單次 `recommendRoute` 呼叫時暫時接收座標，不能寫入 Firestore 或 log。
- 新帳號得到一顆起始種子，空森林直接引導第一個種植任務。
- 光能、水滴與肥料在第一次取得時個別說明，不一次灌輸全部規則。

## 6. 計步與資源經濟

日界線固定為 `Asia/Taipei`。多來源步數以同日最大累計值合併，不相加；各來源的累計只能單調增加。

### 6.1 光能（工作名稱）

- 0–5,000 步：每完成 500 步取得 3 光能，5,000 步共 30。
- 5,001–7,500 步：每完成額外 500 步再取得 4 光能，7,500 步共 50。
- 7,500 步以上仍顯示步數，不再增加光能。
- 1 光能投入後等於 1 成長值。
- 最終名稱可更換，但公式不能未經決策就改動。

### 6.2 水滴

- 完成每日或每週定點 Task 後取得，數量由 Task seed 設定。
- 1 水滴提供 10 成長值。

### 6.3 肥料

- 完成已參加的活動定點 Task 後取得，數量由 Task seed 設定。
- 本次投入增加 20% 成長值；每棵樹每日最多套用一次。

### 6.4 特殊道具

只保留可選的鳥巢／鳥類外觀效果，不製作害蟲、治療、防禦或死亡系統。

所有 Demo 資源不過期、無庫存上限，且標示 `isDemo=true`。

## 7. 任務與路線

### 7.1 內容邊界

Task 是具有獨立 `taskId`、期限與單一公共目的地的不可變實例，分為每日、每週及需手動參加的活動。使用者選擇板橋或西湖等策劃區域後，看見該區所有有效 Task。確切 POI 現勘前只使用明確標示為暫定的版本化 Demo seed。

### 7.2 日期安全的 Must 實作

- Task 可提供 App 內建議步行路線，但使用者採取的實際路徑不影響完成。
- 地圖與導航透過獨立介面整合；其 Web／Android 內部能力由負責人另行確認。
- 每日與每週 Task 自動加入並發水滴；活動 Task 手動參加並發肥料；每個實例最多自動發獎一次。
- 步數只產生光能；種樹屬於 Collection 流程；Task 完成不要求照片。

地圖頁必須顯示：「系統提供的是健走建議，不代表路線安全保證；請遵守交通規則並以現場狀況為準。」

### 7.3 到達判斷

一般模式必須在線，且目的地距離與裝置回報定位精確度都不超過 10 公尺，才解鎖使用者確認。`completeTask` 以伺服器時間、活動參加狀態、距離、精確度與冪等鍵重新驗證後原子發獎；不持久化或記錄使用者原始座標。Demo Mode 提供尚未抵達、精確度不足與可完成三種固定狀態。

## 8. 種樹、培育與回憶林

### 8.1 種植

- 種樹需要一顆種子、主動種植任務、指定公共點與照片。
- 只允許六個種子資料中的公共點；住家／公司不能成為種植點。
- 同地點可持續種新樹，顯示為一個私人「回憶林」marker，避免圖釘重疊。
- 歷史樹數量不限制；首頁最多追蹤三棵。

### 8.2 成長階段

| 累計成長值 | 視覺階段 |
| ---: | --- |
| 0 | 種子 |
| 500 | 幼苗 |
| 1,500 | 小樹 |
| 3,000 | 成熟樹 |
| 5,000 | 大樹 |

5,000 以後不無限放大模型；用年輪、星等、季節裝飾或動物呈現後續累積。

### 8.3 養分投入

- 近距離投入：使用 slider 選光能，勾選水滴／肥料，先預覽扣除量、基本成長、加成與結果，再做不可逆確認。
- 遠端照顧：可投入資源並使一棵樹進入 `harvestReady`，但不能收成 mock 小樹點。
- 正常模式約 150 公尺內才可收成；Demo Mode 可模擬 proximity。

### 8.4 收成與併發規則

- 每累積跨過 5,000、10,000、15,000……門檻，可收成 50 mock 小樹點；樹不消失、不重設。
- 每帳號每日最多收成一次。
- 全帳號同時最多一個未領 `harvestReady`；不建立多筆待領佇列。
- 若帳號已有待領里程碑、今日已收成，或本次投入會跨過兩個以上不可領門檻，`nurtureTree` 以 transaction 原子拒絕，不扣資源。
- 前端預覽最大允許投入，避免使用者反覆試錯。

### 8.5 回憶

樹木詳情呈現種植日期、照片、當日步數與任務回憶。重訪可給季節徽章／葉片收藏，不重複發小樹點。所有森林與照片預設私密。

## 9. Mock 小樹點與社交證據

- 每個樹木里程碑示範入帳 50 mock 小樹點。
- 目錄示例：飲品優惠 30、綠色運輸優惠 50、ESG 植樹捐贈 50。
- 畫面與 ledger 明確標示 Demo，不能讓人誤認為真實點數或可兌現權利。
- 經濟敘事參考現有健康吧比例：5,000 步 30 活動積分、7,500 步 50、5,000 活動積分兌 50 小樹點；CAT WALK 不會讓一次普通健走直接產出數十小樹點。
- 排行榜與好友投入只用 seed data。好友投入只能影響協作外觀、裝飾或居民，不增加樹主人的金錢性收成進度。

## 10. 提醒

- 首頁下班提醒卡為 Must。
- 使用者可設定時間，預設 17:30；完成每日目標後抑制提醒。
- 提醒顯示剩餘步數與建議任務時間。
- Android opt-in local notification 為 Should；Web 提供預覽。FCM 與背景 geofence 不做。

## 11. Demo Mode 與失敗處理

Demo Mode 必須有明顯 badge、設定入口、步數速度、模擬到達、晴／雨／陰／夜外觀、重設，以及五分鐘／兩分鐘一鍵種子。所有 Demo 資料與正常資料隔離。

| 失敗 | 必備退路 |
| --- | --- |
| Gemini | 規則式推薦 |
| 即時路線服務 | 版本化模板路線 |
| GPS 拒絕 | 手動／模擬到達 |
| 相機拒絕 | 選擇既有圖片 |
| 照片上傳失敗 | 本機 pending、可重試 |
| GCP／網路 | Seeded local Demo Mode |
| WebGL | 2D WebP／SVG／CSS 樹 |
| Google 登入 | 準備好的 Demo identity |

## 12. 平台與非功能需求

- Must：Windows 最新及前一版 Chrome／Edge、1280×720 以上；360×800 以上響應式。
- Should：Samsung Galaxy S22+ Chrome 與 APK WebView；native auth、camera、local notification。
- 首頁目標約 3 秒可互動；本機 UI 操作約 200ms 內回應。
- 外部路線／Gemini 8 秒後進入 fallback。
- Traditional Chinese only。
- 測試照片只用內部同意素材；展示後七日內清除 Demo 帳號與照片。
- 每個 Must story 遵守 `CONTEXT.md` 的 Definition of Done。

## 13. 優先級

### Must

Web 登入/onboarding、首頁與模擬步數、六個任務、模板路線推薦／地圖／提醒、照片、三資源、多樹與回憶林、養分交易與收成保護、錢包／兌換／ESG、Firebase 五個 callable functions、Security Rules、seed／reset、Demo Mode 與展示退路。

### Should

Android APK、native Google Sign-In／camera／local notification、Gemini 偏好解析、seeded 排行榜與好友投入。

### Could

Health Connect、真實連續 GPS、Three.js／粒子／鳥巢。

## 14. 仍需外部確認

- 公司是否允許以 Firebase App Distribution 把 signed APK 裝到私人 S22+。
- Azure Boards 是否確為 Agile 或繼承自 Agile 的 Process，以及實際欄位名稱。
- 六個實體公共 POI 的現勘與品牌／場域核可。
- `光能` 與 `Cathay Go｜大樹同行` 的最終內部命名。
- Three.js 必須通過兩人日 spike，且永遠不能成為主要流程相依項。
